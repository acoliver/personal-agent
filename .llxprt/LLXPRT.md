- PersonalAgent Linux KDE tray: the root cause of the "no icon shows" bug was TWO issues: (1) ksni's default `tokio` feature caused a zbus panic ("there is no reactor running") that killed the tray worker thread before it could register with the SNI watcher — fixed by switching to `ksni = { version = "0.3", default-features = false, features = ["blocking", "async-io"] }`; (2) the tray used `icon_name()` with a freedesktop named icon fallback which was unreliable — fixed by implementing `icon_pixmap()` with inline ARGB32 pixel data decoded from the embedded PNG via a `LazyLock<ksni::Icon>`. Additionally, popup positioning required `WindowKind::PopUp` (not `Normal`) on Linux to set `override_redirect=true` and bypass KWin's window placement policy which was re-centering the popup. The popup anchors to bottom-right, 52px above the taskbar.

- PersonalAgent UI e2e automation: do NOT drive the menu-bar popup with hardcoded window coordinates. On Linux the popup is WindowKind::PopUp; macOS and Windows use WindowKind::Normal. It would not accept focus via System Events `set frontmost`, and its reported geometry can be stale or on another display — clicking blind sends keystrokes into whatever app is actually under the cursor (this put text into Discord on 2026-08-28). Use popout mode instead (the popout icon in the top bar, src/ui_gpui/components/window_icons.rs) to get a normal focusable window. Always re-read window geometry each time and assert `System Events > name of first process whose frontmost is true` equals personal_agent_gpui before typing.

How do I stream tokens from the Responses websocket?

Streaming over the Responses socket

Open the socket first, then send the request frame. The server replies with a response.created event, followed by a run of delta events. Each delta carries a fragment of the assistant message; concatenate them in arrival order.

  • •response.output_text.delta carries the visible text
  • •response.reasoning.delta carries thinking, if enabled
  • •response.completed closes the run
rustwhile let Some(frame) = socket.next().await {    match parse(frame)? {        Event::Delta(text) => buffer.push_str(&text),        Event::Completed => break,    }}

Full protocol notes are in docs/responses-websocket.md.

via gpt-5-codex

And what closes it if the model stalls?

An idle timer. If no frame arrives for the configured window the client sends a close frame and surfaces a timeout to the caller, leaving whatever text had already been buffered.

What this prototype proves

A standalone binary with a hardcoded transcript, rendering through the real markdown pipeline and the real theme, where one press-and-drag selects continuously from the middle of one message, through the model label, through a user bubble, and into the next message. ⌘C copies the lot.

Rendering is unchanged while selecting

Headings stay bold, the code block keeps its background and monospace, the table keeps its grid, the link keeps its underline. Selection paints behind the glyphs; it does not swap in a flat renderer. That was the failure mode of PR #159.

Colors, straight from the theme file

  • background #000000
  • text.primary #6a9955
  • message.userBorder #6a9955 → user bubble fill
  • selection.fg #000000
  • selection.bg #6a9955
Design decision needed. In Green Screen the selection background and the user bubble fill are the same #6a9955, and the selection foreground and the user bubble text are the same #000000. A naive highlight inside a user bubble is invisible: identical pixels selected and unselected. The mockup shows the fix, inverting inside that bubble to black-on-green. Any theme where selection.bg is close to a surface fill has this problem; Green Screen is just where they are identical.
Also visible here. The link in message 2 is #6a9955 on #000000, so it reads fine in the assistant message. Put the same link in a user bubble and it is #6a9955 on #6a9955, which is issue #223.
Note on the assistant bubble. In Green Screen there is no visible assistant container: assistant_bubble_bg resolves to input.bg #000000, the same as the window background, and no border width is set. That is faithful to the shipping app and is why the theme reads like a terminal. Only user messages get a filled bubble.
